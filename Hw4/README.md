# 通用迭代框架的 2 個核心洞見

閱讀並分析 `iter_framework.py` 後，這份程式碼最有價值的本質可歸納為以下 2 點：

---

### 1. 數值演算法本質的極致抽象：「狀態機」解耦業務與控制
程式碼最精妙之處在於用僅僅十幾行的 `generic_iterator`，證明了**無論是物理模擬（RK4）、矩陣分解（QR）、機率圖模型（PageRank）或機器學習（EM / K-Means），本質上全都是同一個數學結構：$S_{k+1} = g(S_k)$**。

* **架構優勢**：將「狀態演化算子（數學核心）」與「流程控制／收斂判定（迴圈邏輯）」徹底分離。
* **工程價值**：新增演算法時，工程師只需專注於撰寫無副作用的狀態轉換式，完全不需要重複撰寫任何計步器、中斷點或迴圈邊界。

---

### 2. 動態型別帶來的多態性是雙刃劍：自由度極高但缺乏型別安全
Python 的動態型別讓 `state` 能在同一個框架內自由切換為**純量（牛頓法）、向量（PageRank）、高維矩陣（QR 法）甚至是異質 Tuple（RK4 的 `(t, y)`）**，展現了極高的泛型抽象能力。

* **潛在風險**：在數值計算中，若狀態形狀（Shape）或型別在更新過程中悄悄跑掉（例如純量誤轉為 0 維陣列），框架無法即時防禦，容易導致隱微的 Bug。
* **改進建議**：若要在正式專案落地，應引入 Python `TypeVar` 與型別標記（Generic Typing），並在框架層加入 NaN/Inf 防護機制，才能在保持簡潔的同時兼顧數值穩定性。
